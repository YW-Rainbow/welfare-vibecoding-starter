# 플랫폼별 참고 정보

> 2026년 8월 기준입니다. 가격, 한도, 리전과 서비스 정책은 시간이 지나면 달라질 수 있으므로 중요한 결정을 내리기 전에 해당 사업자의 공식 문서에서 확인하세요.

| | 핵심 사실 |
|---|---|
| **Supabase 서울** | DB, Auth, Storage, PostgREST는 선택한 프로젝트 리전인 서울에서 운영됩니다. Edge Functions는 기본 실행 위치가 글로벌이므로 호출할 때 리전을 지정해야 합니다. Pro는 월 $25이며 DB 백업과 100GB 파일 저장 공간을 포함합니다. Free에서도 서울 리전을 선택할 수 있지만 자동 백업이 없으므로 주 1회 데이터를 내보내야 합니다. 7일 동안 요청이 없는 프로젝트만 일시 중지되므로 매주 사용하는 소형 앱에는 실용적입니다. 데이터가 연 5만 행 이상이거나 사진 저장량이 많다면 Pro를 검토합니다. 기본 백업은 DB만 포함하며 Storage 파일은 별도로 백업해야 합니다. |
| **Cloudflare** | D1은 리전 힌트만 제공하며 한국 리전만 지정할 수 없으므로 개인정보 국외 이전 검토가 필요합니다. Workers Free는 하루 10만 요청을 제공하고 R2는 이그레스 비용이 없습니다. 기본 관리 UI가 없어 비개발자에게 운영을 인계하기 어렵습니다. |
| **GAS** | Google Workspace 조직 계정을 그대로 인증에 사용할 수 있다는 점이 가장 큰 장점입니다. 구글 시트를 DB처럼 사용할 경우 데이터가 수만 행 이상 쌓이면 조회와 쓰기 성능이 떨어질 수 있습니다. 웹앱 배포에서 "실행: 나"와 "액세스: 모든 사용자" 조합은 사용하지 않습니다(`../rules/gas.md`). |
| **Firebase 서울** | Firestore는 NoSQL DB이므로 조회 방식이 미리 정해진 앱에 적합합니다. 방문·외근 앱에 필요한 오프라인 동기화, 보존기간 만료 데이터를 삭제하는 TTL 정책, count와 sum 집계를 지원합니다. 그러나 DISTINCT COUNT를 직접 지원하지 않아 중복을 제외한 실인원 집계에는 적합하지 않습니다. 문서를 삭제해도 서브컬렉션은 남으므로 재귀 삭제와 잔존 데이터 테스트가 필요하고, Security Rules는 기본 거부로 설정해야 합니다. 종단 분석은 BigQuery 미러로 보완할 수 있지만 관리할 구성 요소와 장애 지점이 하나 늘어납니다. Storage를 사용하려면 결제 카드를 등록하고 Blaze 요금제를 사용해야 합니다. |
| **Azure** | 비영리 기관에 연 $2,000 크레딧을 제공합니다. Korea Central 리전으로 전체 시스템을 구성하면 개인정보 국외 이전 검토 범위를 줄일 수 있고 CSAP '하' 인증을 확인할 수 있습니다. 구성과 운영이 복잡하며 크레딧을 갱신하지 못하면 종량제 요금이 카드로 청구될 수 있으므로 전담 관리자가 있는 기관에만 권장합니다. |
| **GCP** | 서울 리전(`asia-northeast3`)에서 Cloud Run, Firestore, Cloud Functions, Cloud SQL, Cloud Storage를 구성할 수 있습니다. 오프라인 동기화가 중요하면 Firestore를, 관계형 집계가 중요하면 Cloud SQL을 검토합니다. Google 비영리 프로그램의 GCP 크레딧 금액과 국내 제공 여부는 신청할 때 확인해야 합니다. 예산 알림은 과금을 자동으로 차단하지 않으므로 `max instances`, 조회 상한, 비상 중단 절차가 필요합니다. 구현 규칙은 `../rules/gcp.md`를 적용합니다. |
| **로컬 운영(NAS 셀프호스팅)** | 일반적인 소형 시설에는 권장하지 않습니다. 백업, 보안 패치, 물리 보안, 랜섬웨어 대응을 기관이 직접 담당해야 하므로 상주하는 전문가가 있을 때만 검토합니다. 브라우저에 데이터를 저장하는 로컬 퍼스트 앱과는 다른 방식입니다. Tailscale을 사용해 접근을 제한하더라도 서버 운영 책임은 기관에 남고, AI 분석을 위해 해외 API로 데이터를 전송한다면 국외 이전 검토도 여전히 필요합니다. |
