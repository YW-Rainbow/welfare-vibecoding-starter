# 인쇄·PDF·엑셀 입출력 구현 가이드

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> 사회복지 현장에서는 감사, 결재, 지도점검 자료를 종이로 제출하고 실적 자료를 엑셀로 주고받는 경우가 많습니다. 따라서 출력 기능을 요구사항과 데이터 구조를 정할 때부터 함께 설계해야 합니다.
> 출력 요구사항은 기능 개발 뒤에 덧붙이기보다 데이터 테이블을 설계할 때 인쇄 서식과 엑셀 입출력 형식을 함께 정합니다. 이 문서의 구현 패턴은 김종원 선생님의 vehicle-drive-log와 최중호 선생님의 SW_EDMS에서 실제 사용한 코드를 참고했습니다.

## 출력 기능이 필요한 이유

- 감사, 지도점검, 결재 과정에서 종이 문서를 요구할 수 있습니다.
- 지자체, 법인, 다른 기관과 실적 자료를 교환할 때 엑셀 형식을 주로 사용합니다.
- 앱을 더 이상 운영하지 못하더라도 기관이 데이터를 표준 파일 형식으로 내보낼 수 있어야 합니다.
- 기존 명부와 기록을 새 앱으로 옮기려면 엑셀 가져오기 기능이 필요합니다.

출력과 엑셀 입출력은 `requirements.md`의 백업과 인수인계 요건, `../data/record-integrity.md`의 보관 등급과도 연결됩니다.

## 구현할 기능을 먼저 구분합니다

| 기능 | 설명 | 주요 용도 |
|---|---|---|
| **현재 화면 인쇄** | 사용자가 보고 있는 기록 한 건이나 화면의 본문을 인쇄합니다. | 결재 문서, 개별 기록 |
| **지정 서식 출력** | 법정서식이나 기관 양식과 같은 레이아웃으로 데이터를 배치합니다. | 운행일지, 출석부, 실적표 |
| **엑셀 내보내기** | 조회 결과를 `.xlsx` 파일로 생성합니다. | 실적 보고, 백업, 외부 제출 |
| **엑셀 가져오기** | `.xlsx` 파일을 읽고 검증한 뒤 DB에 저장합니다. | 기존 기록 이관, 명부 초기 등록 |

## 브라우저 인쇄를 기본으로 사용합니다

일반적인 문서 출력은 별도의 PDF 생성 라이브러리보다 브라우저의 `window.print()`를 우선 사용합니다.

jsPDF 같은 라이브러리로 한글 PDF를 생성하려면 수 MB 크기의 한글 글꼴 파일을 포함해야 합니다. 글꼴을 포함하지 않으면 한글이 사각형으로 표시될 수 있습니다. 브라우저 인쇄는 사용자의 운영체제에 설치된 글꼴을 사용하고 인쇄 대화상자에서 “PDF로 저장” 기능도 제공하므로 구현 범위가 줄어듭니다.

### 두 가지 인쇄 방식

| 방식 | 구현 방법 | 적합한 경우 | 참고 사례 |
|---|---|---|---|
| **현재 화면을 인쇄** | `@media print`에서 사이드바와 버튼을 숨기고 본문만 출력합니다. | 기록 한 건, 결재 문서 | SW_EDMS |
| **인쇄용 HTML 생성** | 데이터로 인쇄 전용 HTML을 생성하고 새 창에서 인쇄합니다. | 여러 건, 여러 페이지, 지정 서식 | vehicle-drive-log |

인쇄용 새 창을 사용하는 경우 브라우저의 팝업 차단을 처리해야 합니다. 팝업이 차단되면 `alert()` 대신 현재 화면에 팝업 허용 방법을 안내하세요.

### 공통 CSS

```css
@page { size: A4 portrait; margin: 10mm; }        /* 가로 방향은 landscape */
@media print { .no-print { display: none !important; } }
body { font-family: 'Malgun Gothic', '맑은 고딕', 'Noto Sans KR', sans-serif; }
```

글꼴 fallback은 Windows, macOS, Android 환경에서 사용 가능한 한글 글꼴을 순서대로 지정합니다. 기관에서 사용하는 PC와 프린터에서 테스트해 한글이 정상적으로 표시되는지 확인해야 합니다.

## 결재란 구현

기관마다 직급과 결재선이 다르므로 결재란을 코드에 고정하지 않고 관리자 설정으로 관리합니다.

- 결재란은 문서 오른쪽 위에 표 형태로 배치합니다.
- 직급은 최대 다섯 칸까지 설정할 수 있게 하고, 기관 관리자가 직급 이름을 변경할 수 있게 합니다.
- 전자결재를 사용하는 기관을 위해 결재란 표시 여부를 설정할 수 있게 합니다.
- 결재란은 첫 페이지에만 표시합니다. 다음 페이지에서는 `visibility: hidden`을 사용해 내용은 숨기되 같은 높이의 공간을 유지하면 페이지마다 본문 시작 위치가 달라지는 문제를 막을 수 있습니다.
- 도장 이미지를 사용한다면 결재 시점의 이미지를 문서에 복사해 고정합니다. 현재 도장 파일의 URL만 참조하면 나중에 이미지를 교체했을 때 과거 문서의 도장도 함께 바뀔 수 있습니다(`../data/record-integrity.md` 원칙 5).

## 여러 페이지로 나누기

자유 입력 필드가 있는 표를 “페이지당 20행”처럼 행 수만 기준으로 분할하면 페이지가 깨질 수 있습니다. 주소, 사유, 비고가 두세 줄로 늘어나면 20행의 실제 높이가 A4 한 페이지를 넘기 때문입니다.

| 테이블 구조 | 권장 방식 |
|---|---|
| 날짜, 금액, 건수처럼 모든 셀의 높이가 일정함 | 페이지당 행 수를 고정해 분할 |
| 목적지, 비고, 사유처럼 높이가 달라지는 필드가 있음 | 숨겨진 컨테이너에 먼저 렌더링해 실제 높이를 측정한 뒤 남은 페이지 높이에 맞게 분할(vehicle-drive-log `pageFit.ts`) |

구현 복잡도를 줄여야 한다면 인쇄물에서 자유 입력 필드를 한 줄로 제한하고 넘치는 내용에 말줄임표를 적용할 수 있습니다. 화면에서는 전체 내용을 제공하고 출력물에서만 한 줄로 제한합니다.

어떤 방식을 사용하든 각 페이지에 문서 제목과 테이블 헤더를 반복합니다. 마지막 페이지의 행 수가 지정 서식보다 적으면 빈 행을 추가해 서식의 높이를 유지합니다.

## 지정 서식 구현

법정서식과 외부 기관이 정한 양식은 열, 행, 칸 수를 임의로 변경하지 않습니다.

- 일별 운행일지가 12칸으로 정해져 있다면 데이터가 3건이어도 12칸을 출력하고 나머지는 빈 행으로 채웁니다.
- 기관 내부에서 필요한 추가 정보는 지정 서식의 열을 변경하지 말고 테이블 위나 별도 영역에 표시합니다.
- 원본 PDF나 한글 파일과 출력 결과를 나란히 놓고 필드 이름, 칸 수, 페이지 구성을 확인합니다.
- 화면용 테이블과 인쇄용 서식은 별도 컴포넌트 또는 템플릿으로 구현할 수 있습니다. 같은 데이터 모델을 사용하되 레이아웃은 각각의 용도에 맞게 구성합니다.

## 엑셀 내보내기

브라우저에서 `.xlsx` 파일을 생성할 때는 SheetJS(`xlsx`)를 사용할 수 있습니다. 일반적인 데이터 내보내기에는 서버가 필요하지 않습니다.

- **열 이름은 현장에서 사용하는 한글 용어로 작성합니다.** 예를 들어 내부 필드명이 `startKm`이더라도 엑셀 헤더는 `출발Km`로 표시합니다. 외부 제출 양식과 같은 열 이름을 사용하면 복사와 검증이 쉬워집니다.
- **열 너비를 지정합니다.** 너비를 지정하지 않으면 값이 `#####`로 표시되거나 사용자가 모든 열을 다시 조정해야 합니다.
- **날짜는 엑셀 날짜 타입으로 저장합니다.** 문자열이 필요하다면 `2026-09-04`처럼 하나의 형식으로 통일합니다.
- **개인정보 열은 기본 내보내기 대상에서 제외합니다.** 업무상 필요한 경우에만 체크박스로 이름과 연락처 같은 열을 포함하게 합니다.
- **파일 이름에 대상과 기간을 포함합니다.** 예: `운행일지_2026-09.xlsx`. `다운로드(3).xlsx`처럼 자동 생성된 이름은 파일을 구분하기 어렵습니다.
- **라이브러리는 사용자가 내보내기 버튼을 누를 때 동적으로 import합니다.** 초기 번들 크기와 화면 로딩 시간을 줄일 수 있습니다.
- **내보내기 작업을 접근 로그에 기록합니다.** 누가 언제 어떤 조건으로 몇 건을 내보냈는지 저장합니다.

기록 종류별로 내보내기 함수는 분리하되 여러 종류의 데이터는 하나의 workbook에 sheet별로 구성할 수 있습니다. 기관별 선택 필드는 실제 값이 있는 경우에만 엑셀 열에 포함합니다.

## 엑셀 가져오기

엑셀 가져오기는 기존 명부와 기록을 새 앱으로 옮길 때 사용합니다. `../data/ssot.md`의 데이터 이관 원칙인 **원본 보존 → 정규화 → 매핑 테이블 작성 → dry-run → 표본 검증 → 관리자 승인** 순서를 적용합니다.

1. **미리보기**: 파일을 선택하면 첫 20행을 화면에 표시합니다. 열 매핑과 오류 건수를 확인하기 전에는 DB에 저장하지 않습니다.
2. **열 매핑 확인**: `성명`, `이름`, `name`처럼 파일마다 다른 열 이름을 앱의 필드에 자동 매핑한 뒤 사용자가 수정할 수 있게 합니다.
3. **행 단위 검증**: 오류가 있는 한 행 때문에 파일 전체를 거부하지 않습니다. `../data/ssot.md`의 품질 등급 A~D를 부여하고 D등급 행만 보류합니다.
4. **엑셀 타입 변환**: 엑셀 날짜 serial number(예: `45000`)를 날짜로 변환합니다. 전화번호와 ID 앞의 0이 사라지지 않도록 문자열 필드도 별도로 처리합니다.
5. **중복 확인**: 이용자ID를 우선 사용합니다. ID가 없다면 이름과 생년월일이 같은 후보를 보여 주고 담당자가 직접 선택하게 합니다. 자동으로 병합하지 않습니다.
6. **처리 결과 제공**: 저장, 보류, 실패 건수를 표시하고 보류된 행을 엑셀로 다시 다운로드할 수 있게 합니다.
7. **rollback 지원**: 같은 업로드에서 생성된 행에 업로드 ID를 기록합니다. 잘못 가져온 경우 해당 ID로 생성된 데이터를 한 번에 되돌릴 수 있게 합니다.

가능하면 SheetJS를 사용해 브라우저에서 원본 엑셀 파일을 파싱합니다. 그러면 개인정보가 포함된 원본 파일을 서버에 업로드하지 않고 검증된 행만 DB에 전송할 수 있습니다. 서버에서 파싱해야 한다면 처리 직후 원본 파일을 삭제하고 파기 로그를 남깁니다.

## 인쇄물과 엑셀 파일의 개인정보 보호

종이와 엑셀 파일도 개인정보 처리 대상입니다. 출력물과 내보낸 파일이 프린터, 공용 폴더, 이메일에 남지 않도록 다음 항목을 구현하고 운영 절차에 포함합니다.

- 민감정보가 포함된 인쇄 작업을 접근 로그에 기록합니다.
- 출력물 바닥글에 출력자와 출력 일시를 자동으로 표시합니다. 개인정보가 포함되면 “대외비” 같은 취급 표시도 추가합니다.
- 보존기간이 끝난 종이 문서도 `../../ops/destruction-log.md`의 파기 대장에 기록합니다.
- 엑셀 파일에는 개인정보 열을 기본으로 포함하지 않습니다. 개인정보가 필요하다면 수신자와 사용 목적, 반출 건수를 접근 로그에 남깁니다.

## 플랫폼별 구현 방식

| 경로 | 현재 화면 인쇄 | 지정 서식 출력 | 엑셀 내보내기 | 엑셀 가져오기 |
|---|---|---|---|---|
| **C. GAS+시트** | 웹앱은 브라우저 인쇄를 사용하고 구글 시트 자체도 인쇄할 수 있습니다. | 출력용 시트를 만들어 PDF로 내보냅니다. 여러 문서를 PDF 하나로 합치려면 pdf-lib(PDFLib.gs)를 사용하거나 출력용 시트에 여러 문서를 배치합니다. | 구글 시트의 파일 › 다운로드 기능을 사용합니다. | 시트에 붙여 넣은 뒤 Apps Script에서 검증하고 명부에 반영합니다. |
| **A. CF+Supabase** | 브라우저 인쇄 | 인쇄용 HTML 생성 후 브라우저 인쇄 | SheetJS 또는 Table Editor의 CSV 내보내기 | SheetJS로 브라우저에서 읽고 검증한 뒤 저장 |
| **F. Firebase** | 브라우저 인쇄 | 인쇄용 HTML 생성 후 브라우저 인쇄 | SheetJS | SheetJS |
| **D. CF 올인원** | 브라우저 인쇄 | 인쇄용 HTML 생성 후 브라우저 인쇄 | SheetJS | SheetJS |

GAS 경로에서 여러 결재 문서를 PDF 하나로 묶어야 한다면 개발을 시작하기 전에 pdf-lib와 출력용 시트 가운데 구현 방식을 선택합니다. 화면 개발이 끝난 뒤 결정하면 출력 데이터 구조와 페이지 구성을 다시 설계해야 할 수 있습니다.

## 배포 전 체크리스트

- [ ] 화면의 모든 테이블에 필요한 인쇄 기능이 있거나, 인쇄하지 않는 이유가 요구사항에 기록되어 있다.
- [ ] Windows와 macOS 등 다른 환경에서 한글이 정상적으로 출력된다.
- [ ] 여러 페이지를 출력할 때 페이지마다 제목과 테이블 헤더가 표시된다.
- [ ] 결재란은 첫 페이지에만 표시되고 다음 페이지의 본문 시작 위치가 동일하다.
- [ ] 지정 서식의 열, 행, 칸 수가 원본과 같다.
- [ ] 엑셀 열 이름이 한글이고 열 너비가 지정되어 있다.
- [ ] 날짜가 엑셀 날짜 타입 또는 합의한 문자열 형식으로 저장된다.
- [ ] 개인정보 열이 기본 내보내기 대상에서 제외되어 있다.
- [ ] 인쇄와 파일 내보내기가 접근 로그에 기록된다.
- [ ] 엑셀 가져오기에 미리보기, 행 단위 검증, rollback 기능이 있다.

## AI에게 전달할 출력 요구사항

```
인쇄
- 기본 방식은 브라우저 인쇄(window.print) 사용
- @page로 A4 크기 설정, @media print로 화면용 요소 숨김
- 글꼴 fallback: 'Malgun Gothic','맑은 고딕','Noto Sans KR',sans-serif
- 여러 페이지에서는 제목과 테이블 헤더 반복
- 결재란은 첫 페이지에만 표시하고 다음 페이지에는 같은 높이의 공간 유지
- 자유 입력 필드는 출력물에서 한 줄로 제한하고 말줄임표 적용
- 지정 서식은 원본과 같은 칸 수 유지, 부족한 데이터는 빈 행으로 출력
- 바닥글에 출력자와 출력 일시 표시, 개인정보가 있으면 취급 표시 추가
- 팝업 차단 시 alert 대신 현재 화면에 안내 표시

엑셀 내보내기
- SheetJS(xlsx)는 내보내기 버튼을 누를 때 동적으로 import
- 한글 열 이름과 현장 양식의 용어 사용, 열 너비 지정
- 날짜는 엑셀 날짜 타입으로 저장
- 개인정보 열은 체크박스로 선택한 경우에만 포함
- 파일 이름에 대상과 기간 포함: 운행일지_2026-09.xlsx
- 반출 대상과 건수를 접근 로그에 기록

엑셀 가져오기
- 가능하면 브라우저에서 파싱하고 원본 파일을 서버에 저장하지 않음
- 첫 20행 미리보기와 열 매핑 확인 제공
- 오류 행은 전체 작업을 중단하지 않고 품질 등급 A~D로 표시
- 엑셀 날짜 serial number를 날짜로 변환하고 전화번호 앞의 0 유지
- 업로드 ID를 각 행에 기록해 rollback 지원
```
