# Google Apps Script + Google Sheets 개발 기준(경로 C)

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> 적용 대상: Google Workspace 조직 내부에서 사용하는 P등급 이하의 소규모 앱
> 기준일: 2026-08
> 이 문서는 `agentic.md`와 함께 적용합니다.

이 문서의 보안·권한·파기 결과는 충족해야 합니다. 나머지 설정과 구현 예시는 소규모 기관을 위한 기본값이며, 같은 결과를 더 단순하게 달성할 수 있다면 이유와 검증 방법을 남기고 바꿀 수 있습니다.

## 보호해야 할 조건

### 권장 배포 설정

- 조직 내부용 앱은 실행 사용자를 **웹 앱에 액세스하는 사용자**, 액세스 권한을 **조직 내 사용자**로 설정하는 방식을 우선 검토합니다.
- 개인정보를 다루는 앱에서 `실행 사용자: 나`와 `액세스 권한: 모든 사용자`를 함께 사용하지 않습니다. 이 설정은 로그인하지 않은 방문자가 개발자 계정의 권한으로 스크립트를 실행할 수 있게 합니다.

### 모든 조회·수정 함수에서 사용자와 권한 확인

```javascript
function doGet(e) {
  const email = Session.getActiveUser().getEmail();
  if (!email) return unauthorized_();          // 사용자 인증
  if (!canAccess_(email, e.parameter.id)) {    // 이 사용자가 해당 행에 접근할 권한이 있는지 확인
    return forbidden_();
  }
  // 이후 로직
}
```

로그인 성공과 데이터 열람 권한은 별개의 조건입니다. `e.parameter.id`를 그대로 사용해 행을 반환하면 IDOR 취약점이 생기므로 각 요청에서 해당 행에 대한 접근 권한을 확인합니다.

### 데이터 시트 관리

- 데이터 시트는 앱 전용 폴더에 두고 다른 사용자에게 직접 공유하지 않습니다. 조회와 수정은 앱에서만 허용합니다. 시트 링크를 공유해야 한다는 요구가 있으면 필요한 항목만 보여 주는 읽기 전용 화면을 만듭니다.
- Google Sheets는 데이터베이스가 아닙니다. 연간 수만 행 이상이 예상되거나 여러 사용자의 동시 쓰기가 많다면 `../docs/workflow.md`의 경로 A를 검토합니다.

### 접근 로그

- 별도 로그 시트에 개인정보의 조회·수정·삭제·출력마다 `[접속 일시, 계정, 수행 업무, 대상 행 ID]`를 기록합니다. GAS 웹앱에서는 접속지 IP를 안정적으로 확보할 수 없으므로 이 한계를 내부관리계획에 기록합니다.
- 민감정보 처리 시스템의 접속기록은 적용되는 법적 기준에 따라 필요한 기간 동안 보관합니다. 개인정보 원본을 파기하더라도 접속기록의 보관 기간이 끝나지 않았다면 로그를 삭제하지 않습니다.
- 로그 시트도 직접 공유하지 않습니다. 이상 조회가 있는지 확인하는 정기 점검 일정을 기관 캘린더에 등록합니다.

### HTML 출력과 XSS 방지

사용자 입력값을 문자열로 연결해 HTML을 만들지 않습니다. `HtmlService.createTemplate`을 사용하고 출력값을 이스케이프 처리합니다.

### 인쇄·PDF·엑셀의 권장 기본값

자세한 기준은 `../docs/requirements/print.md`를 참고합니다.

- 웹앱 화면은 `window.print()`와 `@media print`를 사용해 브라우저에서 인쇄합니다. 이 방식은 사용자의 컴퓨터에 설치된 한글 글꼴을 사용하므로 PDF 라이브러리의 글꼴 호환 문제를 줄일 수 있습니다.
- 기관 서식은 별도의 출력용 시트를 만들고 `getAs(MimeType.PDF)` 또는 내보내기 URL로 PDF를 생성합니다. 용지, 여백, 출력 범위를 명시하고 업무용 데이터 시트를 그대로 출력하지 않습니다.
- 여러 건을 하나의 PDF로 합쳐야 한다면 처음부터 구현 방법을 결정합니다. `pdf-lib`를 스크립트 파일로 포함해 건별 PDF를 합치거나, 출력용 시트에 여러 건을 배치해 한 번에 내보낼 수 있습니다. 문서별 페이지 구분이 중요하면 전자를 사용합니다.
- 엑셀 내보내기는 필요한 열만 포함한 전용 시트를 통해 제공합니다. 개인정보 열이 포함된 원본 시트 전체를 다운로드하게 하지 않습니다.
- 엑셀 가져오기는 원본을 별도 시트에 보존한 뒤 Apps Script로 항목과 값을 검증해 명부에 반영합니다. 기존 값과 새 값의 대응표를 남기는 방법은 `../docs/data/ssot.md`를 참고합니다.

### 삭제 완결성

- 레코드를 삭제할 때 연결된 Google Drive 파일도 함께 삭제합니다. 즉시 삭제하기 어렵다면 삭제 대기 폴더로 옮기고 정해진 일정에 일괄 파기합니다.
- `retention_until` 열에 보관 만료일을 기록하고 시간 기반 트리거로 만기 데이터를 파기합니다.
- 파기 결과는 별도의 파기 대장 시트에 기록합니다.

## 동시 사용자가 늘어날 때 검토할 방법

여러 사용자가 동시에 저장하면서 지연이나 충돌이 발생하면 실제 병목을 측정한 뒤 아래 방법 가운데 필요한 것을 선택합니다. 번호는 적용 순서를 뜻하지 않습니다.

### 1. LockService 적용 구간을 줄인다

읽기와 계산은 lock을 획득하기 전에 처리하고, lock 안에서는 쓰기만 수행합니다.

```javascript
const data = sheet.getDataRange().getValues();   // lock 밖에서 읽기
const newRow = compute(data);                     // lock 밖에서 계산
lock.waitLock(30000);
sheet.appendRow(newRow);                          // lock 안에서는 쓰기만 수행
lock.releaseLock();
```

### 2. 사용자별 입력 시트를 분리한다

직원별 스프레드시트에 입력하고 시간 기반 트리거로 마스터 시트에 통합합니다. 같은 파일에 동시에 쓰는 충돌을 줄일 수 있지만, 통합 트리거가 실패하면 집계에서 기록이 누락될 수 있으므로 실패 알림과 재처리 절차가 필요합니다.

### 3. 입력용 시트와 조회용 시트를 분리한다

입력용 시트에는 새 행을 추가하기만 하고, 트리거가 조회용 시트를 갱신하게 합니다. 입력과 복잡한 조회가 같은 시트를 점유하는 시간을 줄일 수 있습니다.

### 4. 단순한 입력은 Google Forms로 전환한다

신청 접수, 출결, 만족도처럼 정형화된 입력은 Google Forms가 적합할 수 있습니다. 기존 도구로 요구사항을 충족할 수 있다면 별도의 앱을 만들 필요가 없습니다.

다음 방식은 사용하지 않습니다.

- CacheService에 입력값을 임시로 모은 뒤 시트에 저장하는 방식: 캐시는 영구 저장소가 아니므로 기록이 유실될 수 있습니다.
- 연도별로 시트를 분리하는 방식: 스크립트 lock 경합을 해결하지 못하고 여러 해의 데이터를 분석하기 어렵게 만듭니다.

위 조치를 적용해도 성능과 운영 문제가 계속되면 Google Sheets를 데이터베이스로 사용하는 구조를 중단하고 `../docs/workflow.md`에서 경로 A를 다시 검토합니다.

## clasp와 Git 사용

브라우저의 Apps Script 편집기에 코드를 붙여 넣는 방식은 설치가 필요 없어 소규모 작업을 시작하기 쉽습니다. Claude Code나 Codex 같은 에이전트형 도구는 로컬 프로젝트 파일이 필요하므로 처음부터 clasp와 Git을 사용합니다. 채팅에서 코드를 받아 직접 붙여 넣는 방식이라도 다음 조건이 생기면 clasp로 전환합니다.

- 파일 수가 늘어 복사와 붙여넣기 과정에서 실수가 발생하기 시작한 경우
- 로컬 파일을 직접 수정하는 에이전트형 AI 도구를 사용하려는 경우
- 코드의 백업, 변경 이력, 인수인계가 필요한 경우

clasp로 전환할 때는 다음 규칙을 적용합니다.

1. `clasp login`은 개인 계정이 아니라 기관 공용 계정으로 실행합니다. 로그인 인증 정보가 있는 `.clasprc.json`은 저장소에 커밋하지 않습니다.
2. 저장소는 private으로 설정합니다. 코드에 포함될 수 있는 시트 ID와 폴더 ID도 외부에 노출하지 않습니다.
3. 로컬 파일과 Git을 코드의 원본으로 정하고 브라우저 편집기에서 직접 수정하지 않습니다. 긴급 수정이 필요해 브라우저에서 변경했다면 즉시 `clasp pull`로 로컬에 반영합니다.
4. `clasp push` 전에 Git 커밋을 만들어 배포 내용과 코드 이력을 맞춥니다.
5. `../ops/handover.md`의 소스 코드 위치에 저장소 주소와 `clasp clone <scriptId>` 절차를 기록합니다.
6. 새 프로젝트는 clasp 설정, `AGENTS.md`, 요구사항 문서가 포함된 템플릿을 사용할 수 있습니다: https://github.com/YW-Rainbow/apps-script-vibe-starter

## 운영상 제약

- GAS는 Google Workspace 계정 인증을 활용할 수 있고 Google Sheets를 관리 화면으로 사용할 수 있어 소규모 조직의 도입과 인수인계에 유리합니다.
- Google Sheets의 쓰기 작업은 직렬화되므로 동시 입력이 많으면 lock 경합이 발생합니다. Apps Script에는 실행 시간 제한과 콜드 스타트도 있습니다.
- 매년 새 시트를 만드는 구조는 장기 분석과 이용자별 이력 조회를 어렵게 만듭니다. 이 요구가 중요해지면 경로 A로 이전할 시점입니다.
