# AI 규칙 파일: GAS + 구글시트 (경로 C)

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> **AI에게**: 사용자는 비개발자입니다. 이 파일의 용어를 사용자에게 말할 때는
> 같은 리포의 glossary.md 풀이로 통역하세요.

> 사용법: 이 파일을 AI 대화에 첨부하고 "이 규칙을 지켜서 코딩해줘"라고 지시하세요.
> 적용 대상: Google Workspace 조직 내부용 소규모 앱 (P등급 이하).
> 기준일: 2026-08

## 반드시 지킬 것 (위반 시 코드를 다시 작성한다)

### 1. 배포 설정
- 실행 사용자: **웹 앱에 액세스하는 사용자**
- 액세스 권한: **조직 내 사용자**
- 금지: 개인정보를 다루는 앱에서 "실행: 나" + "액세스: 모든 사용자" 조합.
  이 조합은 익명 방문자가 개발자 권한으로 스크립트를 실행하게 만든다.

### 2. 모든 조회·수정 함수의 첫 부분
```javascript
function doGet(e) {
  const email = Session.getActiveUser().getEmail();
  if (!email) return unauthorized_();          // 본인 확인
  if (!canAccess_(email, e.parameter.id)) {    // 행 단위 권한: 이 사람이 이 행의 담당자인가
    return forbidden_();
  }
  // ... 이후 로직
}
```
- 로그인 통과 ≠ 열람 권한. `e.parameter.id`를 받아 그대로 행을 돌려주는 코드 금지(IDOR).

### 3. 데이터 시트 취급
- 데이터 시트는 앱 전용 폴더에 두고 **사람에게 공유하지 않는다(공유 대상 0명)**.
  조회·수정은 앱을 통해서만. 링크 공유가 필요한 요구가 나오면 읽기 전용 뷰 화면을 만든다.
- 시트는 DB가 아니다: 연 수만 행 이상 예상되면 이 경로가 아니라 경로 A(guide.md)로.

### 4. 접근 로그 (접속기록 — 고시 제8조)
- 별도 로그 시트에 조회·수정마다 `[접속 일시, 계정, 수행 업무(조회/수정/삭제/출력),
  처리한 정보주체(대상 행 ID)]`를 기록한다.
  (접속지 IP는 GAS 웹앱에서 확보 불가 — 이 한계를 내부관리계획에 명시)
- 보관: 민감정보 처리 시스템은 **2년 이상** (기본 1년). 로그 시트는 데이터 만기
  파기 대상에서 **제외** — 데이터를 파기해도 그에 대한 접속기록은 보존기간 동안 유지.
- 로그 시트도 공유 0명. 월 1회 점검(이상 조회 여부)을 기관 캘린더에 등록.

### 5. HTML 출력
- 문자열 조합으로 HTML을 만들지 않는다(XSS).
  `HtmlService.createTemplate` + 스크립틀릿 이스케이프를 사용한다.

### 6. 삭제 완결성
- 레코드 삭제 시 연결된 드라이브 파일도 함께 삭제(또는 삭제 대기 폴더로 이동 후 배치 파기).
- `retention_until` 열을 두고, 시간 기반 트리거로 만기 행을 배치 파기한다.
- 파기 실행 시 파기 대장(별도 시트)에 기록.

## clasp — 코드를 편집기 밖으로 (격상 차선)

GAS 개발은 두 차선이 있습니다. **기본 차선은 브라우저 스크립트 편집기 + AI 채팅 복붙**
— 설치할 것이 없어서 이 경로의 존재 이유(0단계 없음)와 맞습니다. 처음이라면 여기서 시작하세요.

**에이전트형 도구(Claude Code, Codex 등)로 작업한다면 clasp가 격상이 아니라
기본 차선입니다** — 에이전트는 로컬 파일이 있어야 일합니다. 이 경우
rules/agentic.md를 함께 적용하세요. 채팅 복붙 방식이라면, 다음 신호가 올 때
**clasp**(구글 공식 CLI)로 격상하세요:

- 파일이 여러 개로 늘어나 복붙이 실수를 만들기 시작함
- Claude Code, Cursor 같은 **에이전트형 AI 도구**로 코딩하고 싶음 (로컬 파일을 직접 고치고 `clasp push`)
- **승계 요건**: 시트 데이터는 눈에 보이지만, 코드는 스크립트 편집기 안에만 존재한다.
  clasp + git(비공개 저장소)이어야 코드에도 백업·변경 이력·인수인계가 생긴다.

격상 시 규칙:

1. `clasp login`은 개인 계정이 아니라 **기관 공용 계정**으로. 로그인 자격증명 파일
   (`~/.clasprc.json`)은 절대 저장소에 커밋하지 않는다 (`.gitignore` 확인).
2. 저장소는 **private**. GAS 코드에는 시트 ID·폴더 ID가 박히기 마련이고,
   이것이 공개되면 공격 표면이 된다.
3. 진실의 원본은 로컬+git으로 통일: 브라우저 편집기에서 직접 고치지 않는다
   (양쪽 수정은 서로를 덮어쓴다). 급한 핫픽스를 편집기에서 했다면 즉시 `clasp pull`.
4. `clasp push` 전에 git commit — 배포 이력과 코드 이력이 어긋나지 않게.
5. 인수인계 문서(`ops/handover.md`)의 "소스 코드 위치"에 저장소 주소와
   `clasp clone <scriptId>` 절차를 적는다.
6. 맨바닥에서 시작하지 말 것 — clasp 설정·AGENTS.md·PRD 양식이 갖춰진 템플릿을
   클론해서 시작한다: https://github.com/YW-Rainbow/apps-script-vibe-starter

## 알아둘 것

- GAS의 강점: 조직 SSO 공짜, Workspace DPA 우산(수탁자 추가 불필요), 시트 = 관리 UI(승계 용이).
- GAS의 약점: 시트 쓰기 직렬화(동시 쓰기 몰리면 락 경합), 실행 6분 제한, 콜드스타트.
- "매해 새 시트" 패턴은 종단분석을 파괴한다. 그 시점이 경로 A로 이사할 시점이다.
