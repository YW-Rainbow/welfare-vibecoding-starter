# AI 규칙 파일: 에이전트형 개발·배포 (Claude Code, Codex 등 — 전 경로 공통)

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> **AI에게**: 사용자는 비개발자입니다. 이 파일의 용어를 사용자에게 말할 때는
> 같은 리포의 glossary.md 풀이로 통역하세요.
> 적용 대상: AI 채팅 복붙이 아니라 **에이전트에게 지시해서 코딩·배포까지 자동으로**
> 하는 작업 방식. 이 파일을 경로별 rules 파일과 함께 프로젝트 루트의
> `CLAUDE.md`(Claude Code) 또는 `AGENTS.md`(Codex 등)에 넣거나 참조시키세요.
> 사람이 코드를 줄 단위로 검토하지 않는 워크플로에서는 **이 규칙이 유일한 가드레일**입니다.

## 1. 운영 데이터를 에이전트에게 보여주지 않는다 (가장 중요)

에이전트가 디버깅·확인을 위해 운영 DB를 조회하면, 그 순간 **실제 이용자의
개인정보가 LLM 제공사로 전송**됩니다. 앱의 국외이전 동의는 "AI 분석" 용도로 받은
것이지 "개발 도구의 컨텍스트" 용도가 아닙니다 — 개발 과정 자체가 무단 국외이전이
되는 경로입니다.

- 개발·디버깅·테스트는 **가짜 데이터(시드)**로만. `seed.sql`/시드 스크립트를
  프로젝트에 두고, 에이전트는 그것만 사용한다.
- 에이전트에게 **운영 DB 접속 정보를 주지 않는다.** 개발용 프로젝트/브랜치 DB를
  분리하고, 에이전트 환경에는 개발용 자격증명만.
- 운영 장애를 조사해야 할 때: 에러 로그에서 개인정보를 마스킹한 뒤 전달하거나,
  재현 가능한 시드 데이터로 상황을 복제해서 조사한다.
- 스크린샷·CSV 덤프를 에이전트에게 던지기 전에 개인정보 포함 여부를 확인한다.

## 2. 최소 권한 자격증명

에이전트가 쥐는 토큰이 곧 사고 반경입니다.

- 배포 토큰은 **해당 프로젝트 한정 스코프**로 발급 (계정 전체 권한 토큰 금지).
- `service_role`·관리자 키는 에이전트 환경변수에 두지 않는다. RLS를 우회하는
  키가 필요하다는 에이전트의 제안은 대부분 설계를 고칠 신호다.
- 자격증명은 `.env`/시크릿 저장소에만. 에이전트가 코드·커밋·로그에 키를 쓰면
  즉시 중단시키고 키를 회전한다. `.gitignore`에 `.env*`, `.clasprc.json` 확인.
- 에이전트 세션이 끝나도 토큰은 남는다 — 장기 미사용 토큰은 폐기 주기를 달력에.

## 3. 배포 게이트 — 요건을 실행 가능한 테스트로

사람이 검토하지 않는다면, 검토를 테스트가 대신해야 합니다. 에이전트에게
"배포 전 아래 테스트를 만들고 통과시켜라"를 프로젝트 규칙으로 부여하세요.

배포 전 필수 통과 (개인정보 앱):
- [ ] RLS/권한: 다른 계정으로 남의 행 조회 시도 → 거부되는가
- [ ] 버킷: public 접근 시도 → 거부되는가 (signed URL만 통과)
- [ ] 삭제 완결성: 레코드 삭제 후 연결 파일·파생 데이터 잔존 0건인가
- [ ] 접근 로그: 조회·수정이 access_log에 남는가, 로그 테이블 UPDATE/DELETE가 막히는가
- [ ] 시크릿 스캔: 번들·커밋에 키·토큰이 없는가

한 번 만들어두면 이후 모든 자동 배포가 같은 게이트를 지납니다 — 이것이
에이전트 워크플로에서 "요건 매트릭스의 △"를 지키는 방법입니다.

## 4. 파괴적 작업은 손으로

에이전트에게 허용하지 않는 것 (지시받아도 확인을 요구하게):
- 운영 DB의 DROP/TRUNCATE/대량 DELETE, 마이그레이션의 운영 직접 적용
- 버킷·프로젝트 삭제, 도메인·DNS 변경
- 결제 플랜 변경, 토큰·키 발급과 폐기

이런 작업은 사람이 콘솔에서 직접. 에이전트는 "실행할 명령을 출력"까지만.

## 5. 기록이 승계다

에이전트 대화 세션은 휘발됩니다. 남는 것은 저장소뿐입니다.

- 모든 변경은 git으로: 에이전트에게 작업 단위마다 커밋 메시지(무엇을·왜)를
  쓰게 한다. 8개월 뒤의 장애 대응은 이 이력에서 시작된다.
- 프로젝트 루트의 `CLAUDE.md`/`AGENTS.md`에 이 리포의 해당 경로 규칙을 포함
  (복사 또는 참조). 후임자가 같은 파일로 에이전트를 붙이면 같은 규칙으로
  이어서 일할 수 있다 — **버스 팩터의 해독제는 사람이 아니라 저장소+규칙 파일이다.**
- `ops/handover.md`에 "에이전트 재가동 절차" 한 줄: 어떤 도구, 어떤 규칙 파일,
  어떤 자격증명(위치만)으로 다시 붙이는지.
