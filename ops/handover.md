# 인수인계 체크리스트

앱이 특정 담당자의 계정과 경험에만 의존하면 담당자가 바뀌었을 때 운영을 계속하기 어렵습니다. 앱을 처음 배포할 때부터 이 문서를 작성하고 변경 사항을 계속 갱신합니다.

## 앱 기본 정보

- [ ] 앱 이름, 용도, 사용 부서:
- [ ] 접속 주소(URL):
- [ ] 플랫폼 경로(`../docs/workflow.md` 기준 A/B/C/D):
- [ ] 데이터 등급(S/P/N)과 판정 근거:
- [ ] 최초 제작일, 제작에 사용한 AI 도구, 규칙 파일 버전:
- [ ] 사람을 기록하는 앱이라면 수집 항목, 접근 권한, 보관 기간, `../docs/assess/ethics.md`의 다섯 질문에 대한 결정 내용과 결정일:
- [ ] 기록별 보관 등급(`../docs/data/record-integrity.md` 기준 0~5)과 판정 근거:

## 기관 계정

- [ ] Supabase, Cloudflare, Google 등 플랫폼 계정의 ID와 관리 위치:
- [ ] 개인 계정으로 만든 서비스가 있다면 기관 관리 계정으로 이전했는가:
- [ ] 2단계 인증 수단이 특정 직원의 개인 휴대전화에만 등록되어 있지 않은가:
- [ ] 결제 수단의 등록 여부, 명의, 변경 절차:

## 코드와 설정

- [ ] 소스 코드 저장소 주소와 private 설정 여부:
- [ ] 처음 보는 담당자가 따라 할 수 있는 배포 명령과 절차:
- [ ] API 키와 토큰 목록 및 보관 위치. 실제 값은 이 문서에 적지 않음:
- [ ] 도메인과 DNS 설정 위치:

## 데이터

- [ ] Table Editor, Google Sheets, 관리 페이지 등 데이터를 조회하는 방법:
- [ ] 데이터베이스와 파일의 백업 위치, 주기, 최근 복구 테스트 일자:
- [ ] 데이터별 보존 기간과 만기 파기 방법:
- [ ] 파기 대장 위치(`destruction-log.md` 양식):

## 개인정보 관련 문서

- [ ] 동의서 양식과 작성된 동의서의 보관 위치:
- [ ] 개인정보 처리방침 게시 위치와 수탁자 목록 최종 갱신일:
- [ ] Supabase 등 사업자의 DPA 체결 여부와 확인 위치:

## 기관 캘린더에 등록할 일정

- [ ] 유료 플랜 결제일과 크레딧 갱신일:
- [ ] 백업 성공 여부 확인과 복구 테스트 주기:
- [ ] 보존 기간이 끝난 데이터의 파기 작업 확인 주기:
- [ ] 접근 로그 점검 주기와 담당자:

## 에이전트형 AI 도구로 개발한 경우

- [ ] 사용한 도구와 규칙 파일 위치(예: Claude Code와 저장소 루트의 `CLAUDE.md`):
- [ ] 저장소 clone, 규칙 확인, 개발용 인증 정보 연결, 테스트 실행까지의 작업 재개 절차:
- [ ] 개발용과 운영용 인증 정보를 분리했으며 에이전트가 운영 데이터베이스에 접근할 수 없는가:

## 장애 대응

- [ ] 앱과 플랫폼에 대해 문의할 수 있는 내부·외부 담당자:
- [ ] 앱을 사용할 수 없을 때 적용할 임시 수기 절차:
- [ ] 장애 발생 시 사용자에게 알리는 방법과 데이터 복구 책임자:
