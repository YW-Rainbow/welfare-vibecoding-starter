# 기관에 AI 에이전트(슬랙 봇 등)를 붙이기 전에 확인할 것

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> Slack, Discord, 카카오톡 같은 메신저나 업무포털에 AI 에이전트를 붙여 기관 전체가 쓰게 하려 할 때 적용합니다. 직원 개인이 자기 컴퓨터에서 Claude Code나 Codex를 쓰는 것은 이 문서의 대상이 아닙니다. 붙이는 방법은 각 도구의 문서와 커뮤니티에 많으므로 여기에는 적지 않고, 붙이기 전에 기관이 정해야 할 것만 적습니다.
> 사실 정보는 2026년 9월 기준입니다. 각 회사의 정책이 몇 달 단위로 바뀌므로 결정 전에 아래 "확인 필요"의 공식 문서를 다시 확인합니다.

## 언제 필요한가

에이전트는 데이터가 있어야 일합니다. 이용자 명부가 단일 원본이고(`../data/ssot.md`), 기관에 공용 데이터와 API가 있을 때(`../data/levels.md` 3단계) 봇은 조회, 요약, 초안 작성, 알림을 할 수 있습니다. 데이터 레이어가 없으면 봇은 답할 데이터가 없어 채팅 상대에 그칩니다. 그 전 단계의 기관은 직원 개인이 쓰는 Claude Code·Codex와 메신저의 공식 앱으로 충분합니다.

"업무포털에 AI 채팅창을 넣고 싶다"는 요구도 대부분 데이터 레이어가 없는 상태에서 화면만 원하는 경우입니다. 포털은 단일 원본을 보여 주는 화면이고, 봇은 그 데이터를 메신저에서 쓰게 하는 또 하나의 화면입니다. 둘 다 데이터 레이어가 먼저입니다.

`../workflow.md`의 시작 전 확인은 여기에도 적용됩니다. 봇으로 자동화하려는 절차가 없어도 되는 절차인지 먼저 봅니다.

## 원칙: 개인 구독으로 기관 봇을 만들지 않습니다

지금 현장에서는 직원 한 명의 구독 계정(Claude Pro·Max, ChatGPT Plus·Pro)으로 로그인한 에이전트를 기관 메신저에 붙여 모두가 쓰는 경우가 많습니다. API 비용을 내지 않아도 되기 때문입니다. 기관 업무에는 다음 세 가지 이유로 맞지 않습니다.

1. **계정의 주인.** 봇이 한 직원의 계정에 묶입니다. 그 직원이 나가면 봇이 멈추고, 그동안 기관 데이터를 개인 명의로 처리한 셈이 됩니다. 한 계정을 여러 사람이 쓰는 것은 대부분의 약관이 금지하는 계정 공유입니다.
2. **한도.** 구독 한도는 그 개인의 것입니다. 기관 전체가 쓰면 낮 시간에 한도가 소진되어 봇이 멈춥니다.
3. **데이터 처리 계약.** 개인 플랜에는 소비자 약관이 적용됩니다. 기관이 요구해야 하는 DPA(개인정보 처리 부속계약)가 없고, 학습 미사용 설정을 사용자가 직접 켜야 합니다. `../requirements/masking.md`의 조건을 충족할 수 없습니다.

기관 봇은 **기관 플랜**(Claude Team·Enterprise, ChatGPT Business·Enterprise)이나 **기관이 결제하는 API 키**로 만듭니다.

정책은 자주 바뀝니다. Anthropic은 2026년 2월 20일 약관에서 구독 계정으로 제3자 도구를 쓰는 것을 금지했고, 4월 4일 OpenClaw·Hermes Agent 같은 제3자 에이전트를 차단했고, 5월 13일 별도 크레딧을 두는 조건으로 다시 허용한다고 발표했고, 6월 15일 그 변경을 보류해 구독 한도에서 차감하는 상태로 두었습니다. OpenAI는 2026년 5월 2일 ChatGPT 구독 계정으로 제3자 에이전트에 로그인해 쓰는 것을 공식 허용했습니다(발표 당시 예시는 OpenClaw였고, Hermes Agent도 같은 Codex 로그인을 씁니다). 넉 달 사이 네 번 바뀐 정책에 기관 업무를 기댈 수 없습니다. 판단의 근거는 정책의 허용 여부가 아니라 계정 구조입니다.

## 선택지

자체 호스팅 에이전트는 두 가지가 널리 쓰입니다. **OpenClaw**는 Slack, Discord, Telegram, WhatsApp 등 20여 개 메신저를 LLM에 연결하는 게이트웨이로, 2026년 8월에 2.0이 나왔습니다. **Hermes Agent**는 Nous Research가 2026년 2월에 낸 MIT 라이선스 에이전트로, 같은 종류의 메신저 게이트웨이와 영구 메모리, 스스로 만드는 스킬을 갖췄습니다. 둘 다 기관 서버에서 실행되고, 코드를 실행하고, 파일과 브라우저에 접근하며, Anthropic·OpenAI·Google API 키와 ChatGPT 구독 로그인(Codex)을 지원합니다. 아래 표에서 두 도구는 같은 조건입니다.

| 방식 | 조건 | 장점 | 확인할 것 |
|---|---|---|---|
| **Claude Tag** (Slack 전용 공식 봇) | Claude Team·Enterprise 플랜, 기관 Slack 워크스페이스 | 서버가 없습니다. 조직 소유자가 한 번 설정하면 채널의 누구나 `@Claude`로 일을 맡깁니다. 관리자가 채널별로 접근 범위를 정하고, 외부 서비스마다 Claude 전용 계정을 만들어 연결하며, 월 지출 한도를 겁니다. 채널 작업은 기관 잔액에서 사용량만큼 과금됩니다 | 공개 베타입니다. Slack만 지원합니다. 사용자당 요금과 별도로 사용량 잔액을 충전하는 예산 집행 방식이 필요합니다. 채널 메모리가 무엇을 기억하는지 관리자가 확인합니다. Anthropic 문서가 "채널의 다른 메시지 지시를 따를 수 있으니 신뢰할 수 있는 대화에서만 쓰라"고 경고합니다 |
| Pro·Max의 Claude Code in Slack | 개인 플랜 | 개인이 자기 코딩 작업을 Slack에서 맡길 수 있습니다 | 각자 자기 계정과 한도로 세션이 실행됩니다. 기관 공용 봇이 아니고 코딩용입니다 |
| **자체 호스팅 OpenClaw 또는 Hermes Agent + ChatGPT Business 사용자 계정** | ChatGPT Business 이상, 기관 서버, 운영 담당자 | OpenAI가 구독 로그인을 공식 허용했고 Business 계정으로 로그인이 됩니다. Business는 학습 미사용이 기본이고 관리자 통제와 중앙 결제가 있습니다. 메신저 20여 종에 붙습니다. 정액입니다 | 봇 전용 사용자 계정을 두는 것이 약관에 맞는지, DPA를 체결했는지, 카카오톡 채널 지원 여부, 사용자 계정 한도. 코드를 실행하는 에이전트를 기관 서버에서 운영하는 보안 책임은 기관에 있습니다 |
| 자체 호스팅 + 기관 API 키 (Anthropic, OpenAI, Google 등) | 기관 결제, 기관 서버, 운영 담당자 | 가장 자유롭습니다. DPA를 체결할 수 있고, Vertex AI 같은 경로로 국내 리전을 고를 수 있습니다 | 종량 과금이라 비용 상한과 알림을 설정합니다. 서버 운영 책임은 위와 같습니다 |
| 자체 호스팅 + 개인 구독 로그인 | 개인 계정 | 가장 저렴합니다 | 개인용에만 씁니다. 기관 봇에는 위 원칙의 세 가지 이유로 맞지 않습니다. Claude 구독은 정책이 계속 바뀝니다 |

Slack을 쓰는 기관은 Claude Tag가 가장 짧은 길이고, Slack을 쓰지 않는 기관은 자체 호스팅에 기관 플랜이나 API 키를 붙이는 길만 있습니다.

## 데이터

- 봇이 읽을 채널을 목록으로 정합니다. 이용자 정보가 오가는 채널에는 붙이지 않습니다. 붙여야 한다면 `../requirements/masking.md`의 DPA, 국외이전 동의, 마스킹 조건을 먼저 갖춥니다.
- Slack과 Discord 자체도 개인정보 수탁자이고 서버는 국외에 있습니다. 개인정보 처리방침의 사업자 목록에 넣습니다(`../../ops/consent-notes.md`).
- 봇의 메모리에 이용자 정보가 남지 않게 합니다. 무엇을 기억하고 누가 볼 수 있는지 확인합니다.
- 채널에 있는 다른 사람의 메시지가 봇에게 명령이 될 수 있습니다. 외부인이 들어오는 채널에는 붙이지 않습니다.

## 권한과 사람의 확인

`../requirements/ai.md`의 규칙을 봇에 그대로 적용합니다.

- 봇 전용 계정을 만들고 읽기 권한부터 시작합니다. 쓰기, 발송, 삭제, 외부 제출은 사람이 승인하기 전에는 실행되지 않습니다.
- 그런 민감한 요청은 요청한 사람이 허용 목록의 직원인지 봇이 먼저 확인하고, 목록에 없는 사람의 요청은 승인 단계로 넘기지 않고 실행하지 않습니다. 채널의 누구나 봇에게 말할 수 있으므로 사람 승인만으로는 부족합니다.
- 봇이 한 일은 로그에 남기고, 정기적으로 표본을 검수합니다.
- 사람에 관한 결정(자격, 배제, 우선순위)은 봇이 내리지 않습니다.
- 자체 호스팅 에이전트가 파일, 브라우저, 코드 실행에 접근하는 범위를 명시적으로 제한합니다.

## 운영

- 봇 계정, 서버, 자격 증명의 관리자를 정하고 `../../ops/handover.md`에 적습니다. 관리자가 바뀌어도 봇이 멈추지 않아야 합니다.
- 한도가 소진되거나 서비스가 멈췄을 때 사람이 처리하는 절차를 둡니다.
- 사용량 과금이면 월 상한과 알림을 설정하고 예산 집행 방식을 정합니다.
- 중단 절차를 정합니다. Slack 앱을 제거하면 접근이 즉시 회수되는지, 자체 호스팅이면 자격 증명을 폐기하는 순서가 무엇인지 적습니다.

## 판정할 때 확인할 질문

`DECISION.md`의 AI 기능 항목에 답을 기록합니다.

- 봇이 참조할 최초 기록과 API가 있나요? 없으면 봇보다 데이터 레이어가 먼저입니다.
- 어느 채널을 읽고, 그 채널에 이용자 정보가 있나요?
- 봇 계정의 주인은 누구이고, 그 사람이 없어도 봇이 유지되나요?
- 데이터 처리 계약(DPA)과 학습 미사용은 확인했나요?
- 사람 승인 없이 봇이 실행하는 일의 목록은 무엇인가요?

## 확인 필요

2026년 9월에 확인한 사실이고 바뀔 수 있습니다.

1. Anthropic 구독의 제3자 도구 사용 정책. 도움말 문서 "Use the Claude Agent SDK with your Claude plan"의 현행 문구.
2. Claude Tag가 베타를 벗어났는지, Slack 외 메신저 지원 여부.
3. ChatGPT Business에서 봇 전용 사용자 계정을 두는 것이 허용되는지, DPA 체결 절차.
4. OpenClaw와 Hermes Agent의 카카오톡 채널 지원 여부와, OpenAI 공식 허용 문구가 두 도구에 같게 적용되는지.
5. Slack의 DPA와 데이터 저장 위치.
