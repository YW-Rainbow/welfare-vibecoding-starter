# 에이전트 브라우저로 기관 기록과 기존 정보시스템을 맞추기 전에 확인할 것

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> 시설이 법에 따라 입력하는 기존 정보시스템(정부가 운영하는 사회복지시설 정보시스템. 사용자는 흔히 희망이음이라고 부릅니다)과 기관이 따로 쓰는 앱이나 시트를, 에이전트 브라우저로 대조하거나 옮겨 적으려 할 때 적용합니다. 앱을 새로 만드는 일이 아니어도 이 문서를 씁니다.
> 도구 사용법은 적지 않고, 기관이 먼저 정할 것과 안전하게 쓰는 순서만 적습니다. 제품 정보는 2026년 9월 기준이며 `../platform-facts.md`에 둡니다. 이 문서는 법률 자문이 아닙니다.

## 왜 이런 요구가 생기나

시설은 인사, 회계, 후원, 보고, 서비스 이력을 기존 정보시스템에 입력하고, 기관 앱과 시트에도 같은 내용을 적습니다. 두 곳을 잇는 통로(API)가 열려 있지 않으니 같은 사실이 두 곳에 있고, `../data/ssot.md`의 단일 원본 원칙을 구조적으로 어기게 됩니다. 그래서 두 곳을 늘 같게 맞추는 동기화가 필요합니다. 이것을 모두 손으로 하면 불편하고, 사람이 하는 일이라 누락이 생깁니다.

에이전트 브라우저는 사람이 로그인해 둔 브라우저에서 AI가 화면을 보고 클릭하고 입력하는 도구입니다. 통로가 없는 시스템에도 화면으로 들어갈 수 있어서, 이 동기화를 맡기려는 요구가 늘고 있습니다.

이 요구를 막지 않습니다. 사용자가 원하면 아래 조건을 갖춰 안전하게 쓰도록 돕습니다. 갖추지 못한 조건은 "기관 확인 대기"로 판단 기록에 적고, 그 조건이 풀리기 전에는 이용자 정보가 보이는 화면에서 에이전트를 쓰지 않도록 안내합니다.

## 먼저 한 줄로 제안할 더 가벼운 방법

`../workflow.md` 시작 전 확인 4번처럼, 다른 수준의 해법을 하나 제시하고 선택은 사용자가 합니다.

- 기관 앱이 기존 정보시스템의 입력 순서대로 값을 보여 주고 복사하기 쉽게 만듭니다(`../rules/gas.md`의 "희망이음" 항목과 같은 방식). 붙여 넣기는 사람이 하지만 AI가 이용자 정보를 보지 않습니다.
- 기관 내부 양식 가운데 기존 정보시스템과 겹치는 것이 있으면 `form-audit.md`로 없애거나 합칠 수 있는지 봅니다.

## 쓰기 전에 확인할 것

1. **운영 기관의 약관과 보안 규정**: 기존 정보시스템에서 자동화 도구를 쓰는 것과 화면에 보이는 자료를 외부 AI로 보내는 것이 허용되는지 운영 기관에 확인합니다. 확인하지 못했으면 "확인 필요"로 적습니다.
2. **위수탁 협약**: 지자체에서 위탁받아 운영하는 기관이면 협약의 반출 조항을 봅니다(`../requirements/masking.md` 0번). 기존 정보시스템에서 보이는 자료는 반출이 제한될 수 있습니다.
3. **AI 전송 조건**: 에이전트가 화면을 읽으면 화면에 뜬 이용자 정보가 AI 사업자에게 갑니다. 입력을 맡기면 에이전트는 그 정보를 봐야 일할 수 있습니다. 그래서 `../requirements/masking.md`의 "마스킹하지 않고 전송하기 위한 사전 조건"을 그대로 적용합니다. 업무용 계약(DPA)이 있는 기관 플랜이나 유료 API, AI 처리를 위한 국외이전 동의(「개인정보 보호법」 제28조의8 제1항 제1호), 건강 같은 민감정보가 있으면 제23조 동의, 처리방침에 적은 사업자가 필요합니다. 동의를 거부한 이용자의 기록은 사람이 직접 입력합니다.
4. **개인 구독을 쓰지 않습니다**: 직원 개인의 ChatGPT나 Claude 구독을 에이전트 브라우저에 연결해 이용자 정보가 보이는 작업을 하지 않습니다. 소비자 약관이 적용되고 기관의 계약이 없기 때문입니다(`agent.md`의 원칙과 같습니다).
5. **계정과 인증**: 기존 정보시스템의 계정과 인증서는 개인 명의입니다. 에이전트가 입력해도 기록에는 그 사람이 입력한 것으로 남고 책임도 그 사람에게 갑니다. 로그인과 추가 인증(인증서, 2단계 인증, 보안문자)은 사람이 직접 하고, 에이전트가 우회하게 하지 않습니다. 한 사람의 계정으로 다른 사람의 업무를 대신 처리하지 않습니다.
6. **기관의 결정**: 위 확인 결과와 기관의 결정을 판단 기록에 적습니다. 앱이 없으면 `../templates/DECISION.md` 양식을 그대로 써도 됩니다.

## 동기화의 방향을 정합니다

- 기관 기록을 원본으로 둡니다(`../data/ssot.md`의 최초 기록). 기존 정보시스템에는 원본의 값을 옮깁니다.
- 두 곳이 다를 때 어느 쪽이 맞는지 에이전트가 고르지 않습니다. 원본을 따르되, 원본이 비었거나 이상하면 멈추고 사람에게 목록으로 알립니다. 방향이 없으면 에이전트가 틀린 값을 서로 옮겨 적을 수 있습니다.
- 기존 정보시스템의 값을 기관 기록으로 가져오는 역방향 작업은 반출 제한에 걸릴 수 있으므로, 1번과 2번을 확인하기 전에는 하지 않습니다.
- 시스템이 스스로 계산하거나 정하는 값처럼 원본이 기존 정보시스템에 있는 항목이 있다면, 항목마다 어느 쪽이 원본인지 기관이 정해 판단 기록에 적습니다.

## 운영 순서

1. **대조부터**: 도구에 읽기 전용 모드가 있으면 그것으로 시작합니다. 두 곳을 비교해 다른 곳의 목록만 받습니다. 이것만으로 손으로 찾기 어렵던 누락이 드러나고, 에이전트가 화면을 제대로 읽는지도 확인할 수 있습니다.
2. **소량 시험**: 몇 건만 입력하거나 고치게 하고 사람이 모두 검수합니다.
3. **확대**: 건수를 늘려도 저장, 제출, 결재 요청은 사람이 누릅니다. 정해진 시각에 자동으로 돌리는 반복 작업에도 멈춤 지점을 그대로 둡니다(`../rules/agentic.md`의 "결정은 사람이 하고 실행은 AI가 한다"와 같습니다).
4. **작업 기록**: 기존 정보시스템의 기록에는 에이전트의 입력이 사람의 입력과 구분되지 않습니다. 그래서 언제 무엇을 몇 건 대조하고 고쳤는지 기관 쪽에 작업 기록을 남깁니다. 기록에는 실명 대신 이용자 ID를 씁니다.
5. **측정**: 두 곳을 맞추는 데 드는 시간과 찾아낸 어긋남을 세어 둡니다. 이 숫자는 기존 정보시스템에 연계 통로를 요구할 근거가 됩니다.

## 지시문 틀

사이트, 대상, 원본, 금지 행동, 멈춤 지점을 빠짐없이 적습니다. 예시는 다음과 같습니다.

```
기존 정보시스템에서 [메뉴 경로]를 열어 줘. 로그인은 내가 이미 해 두었어.
원본은 시트 "[시트 이름]"이야. 시트의 각 행을 [화면 이름]의 값과 한 건씩 대조해 줘.
다른 곳은 시트 값에 맞춰 화면에 채우되, 저장 버튼을 누르기 전에 멈추고 화면의 값과 시트 값을 표로 보여 줘.
시트에 빈칸이 있거나 값이 이상하면 그 건은 건너뛰고 목록으로 알려 줘.
삭제, 제출, 결재 요청, 다른 메뉴 이동은 하지 마.
인증서나 추가 인증 화면이 나오면 멈추고 나를 불러 줘.
```

## 도구 설정

제품마다 이름과 기본값이 다르므로 공통으로 확인할 것만 적습니다. 알려진 제품의 설정은 `../platform-facts.md`에 있습니다.

- **권한**: 가장 좁게 시작합니다. 읽기 전용에서 시작하고, 파일과 폴더 접근은 필요한 곳만 엽니다.
- **동작 규칙**: 삭제, 제출, 결재, 외부 발송 같은 동작은 매번 묻거나 막는 규칙으로 둡니다.
- **저장된 비밀번호**: 에이전트가 저장된 비밀번호로 로그인하게 두는 설정은 끄거나 잠금을 푼 동안에만 쓰게 바꿉니다. 이 설정을 허용으로 두는 제품도 있습니다.
- **작업 전용 창**: 에이전트는 화면에서 읽은 문장을 명령으로 착각할 수 있습니다. 기존 정보시스템에서 일할 때는 다른 사이트를 함께 열지 않고, 이 일만 하는 창이나 프로필을 씁니다.
- **메모리**: 에이전트의 메모리에 이용자 정보가 남지 않게 하고, 메모리를 얼마나 보관하는지 확인합니다.
- **모델 연결**: 4번대로 개인 구독이 아니라 기관 계약이나 기관이 결제하는 API 키로 연결합니다.

## 판정할 때 확인할 질문

- 더 가벼운 방법을 한 줄로 제안했고, 사용자가 선택했는가
- 운영 기관의 약관과 위수탁 협약을 확인했는가, 아니면 "기관 확인 대기"로 남겼는가
- AI 전송 조건(업무용 계약, AI 국외이전 동의와 민감정보 동의, 처리방침)을 갖췄는가
- 동기화의 방향을 정했고, 원본이 이상할 때 멈추는가
- 로그인, 추가 인증, 저장, 제출은 사람이 하는가
- 작업 기록을 어디에 남기는가

## 확인 필요

- 기존 정보시스템 운영 기관의 자동화 도구 정책과 화면 자료의 외부 전송 허용 여부
- 에이전트 브라우저 제품이 모델 사업자에게 무엇을 보내는지, 학습에 쓰는지, 기관용 데이터 처리 계약이 있는지. 2026년 9월 기준 공식 문서에 적혀 있지 않은 제품이 있습니다.
- 개인정보보호위원회의 생성형 AI 관련 안내의 최신판
