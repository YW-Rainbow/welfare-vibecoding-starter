# 에이전트 브라우저로 정부 업무 시스템과 기관 앱 동기화하기

> 출처·최신판: https://github.com/YW-Rainbow/welfare-vibecoding-starter
> Aside 같은 에이전트 브라우저로 정부 업무 시스템(희망이음 등)과 기관 앱·구글 시트를 대조하거나 옮겨 입력할 때 적용합니다. 앱을 만들지 않고 동기화만 해도 적용합니다.

## 배경

시설이 법이나 지침에 따라 입력하는 정부 시스템에는 대부분 기관이 쓸 수 있는 API가 없습니다. 그래서 인사, 회계, 후원, 서비스 이력을 기관 앱·시트와 정부 시스템에 두 번 입력하고, SSoT(`../data/ssot.md`)가 깨집니다. 두 곳을 손으로 동기화하면 시간이 들고 누락이 생깁니다. 에이전트 브라우저는 사람이 로그인한 세션에서 화면을 읽고 클릭·입력하므로, API 없이 이 동기화를 대신할 수 있습니다.

막지 않고 아래 조건으로 쓰게 돕습니다. 갖추지 못한 조건은 `DECISION.md`에 "기관 확인 대기"로 적고, 그동안에는 이용자 정보가 보이는 화면에서 에이전트를 쓰지 않습니다.

희망이음에서 에이전트 브라우저로 입력해 보니 느리지만 된다는 현장 이야기는 있습니다. 다만 2026년 9월 기준으로 공개된 사례는 없어서, 이 문서에는 사용법이 아니라 쓰기 전에 확인할 것과 주의점만 적습니다.

## 먼저 제안할 대안

`../workflow.md` 시작 전 확인 4번처럼 한 줄로 제안하고 사용자가 고릅니다.

- **복사용 화면**: 기관 앱이 정부 시스템의 입력 순서대로 값을 보여 주고 복사 버튼을 둡니다(`../rules/gas.md`의 "희망이음" 항목). 붙여 넣기는 사람이 하지만 이용자 정보가 AI로 가지 않습니다.
- **양식 정리**: 정부 시스템과 겹치는 기관 내부 양식은 `form-audit.md`로 없애거나 합칩니다.

## 쓰기 전 확인

1. **운영 기관의 약관·보안 규정**: 자동화 도구를 쓰는 것과 화면 데이터를 외부 AI로 보내는 것이 허용되는지 운영 기관(희망이음은 한국사회보장정보원)에 확인합니다. 확인하지 못했으면 "확인 필요"로 적습니다.
2. **위수탁 협약**: 지자체 위탁 기관은 협약의 반출 조항을 봅니다(`../requirements/masking.md` 0번). 정부 시스템의 화면과 다운로드 자료는 반출이 제한될 수 있습니다.
3. **AI 전송 조건**: 에이전트가 화면을 읽으면 화면의 이용자 정보가 모델 사업자에게 전송됩니다. 그래서 `../requirements/masking.md`의 "마스킹하지 않고 전송하기 위한 사전 조건"을 그대로 적용합니다. DPA가 있는 기관 플랜이나 유료 API, 국외이전 근거(처리방침 공개 또는 동의, `../../ops/consent-notes.md` 1절), 건강 같은 민감정보면 제23조 동의, 처리방침의 사업자 기재가 필요합니다. AI 처리를 거부한 이용자의 건은 사람이 직접 입력합니다.
4. **개인 구독 금지**: 직원 개인의 ChatGPT·Claude 구독을 에이전트 브라우저에 OAuth로 연결해 이용자 정보가 보이는 작업을 하지 않습니다. 소비자 약관이 적용되고 기관 DPA가 없기 때문입니다(`agent.md`와 같은 원칙).
5. **계정·인증**: 정부 시스템의 계정과 인증서는 개인 명의입니다. 에이전트가 입력해도 시스템에는 계정 주인이 입력한 것으로 남고, 책임도 계정 주인이 집니다. 로그인, 인증서, 2단계 인증, CAPTCHA는 사람이 처리하고 에이전트가 우회하게 하지 않습니다. 다른 사람의 계정으로 대신 처리하지 않습니다.
6. **기록**: 확인 결과와 기관의 결정을 `DECISION.md`에 적습니다. 앱이 없으면 `../templates/DECISION.md`를 그대로 써도 됩니다.

## 원본 정하기

- 기관 앱·시트를 원본으로 두고, 정부 시스템에는 원본 값을 씁니다. 값은 한쪽 방향으로만 옮깁니다(`../data/ssot.md`의 최초 기록).
- 값이 다를 때 어느 쪽이 맞는지 에이전트가 판단하지 않습니다. 원본이 비었거나 형식이 이상하면 건너뛰고 목록으로 보고하게 합니다.
- 정부 시스템에서 기관 앱으로 가져오는 역방향은 반출 제한에 걸릴 수 있으므로, 1번과 2번을 확인하기 전에는 하지 않습니다.

## 운영 순서

1. **동작 확인**: 인증서 로그인과 보안 프로그램이 에이전트 브라우저에서 되는지, 에이전트가 화면을 제대로 읽는지를 이용자 정보가 없는 화면에서 먼저 봅니다.
2. **대조만**: 두 곳이 다른 건의 목록만 받고, 지시문에 "입력하거나 저장하지 마"를 적습니다. Aside의 `Read only`는 파일 변경만 막고 웹 화면의 클릭과 입력은 막지 않습니다.
3. **소량 시험**: 몇 건만 입력하게 하고 사람이 전부 검수하며, 한 건에 걸리는 시간도 재 봅니다. "저장 전에 멈춰"는 지시일 뿐 설정으로 강제되지 않으므로, 실제로 멈추는지 이 단계에서 확인합니다.
4. **확대**: 건수를 늘려도 저장, 제출, 결재 요청 버튼은 사람이 누릅니다. 예약 실행에서도 마찬가지입니다. 결정은 사람이 하고 실행은 AI가 한다는 `../rules/agentic.md`의 원칙과 같습니다.
5. **작업 로그와 측정**: 정부 시스템의 로그로는 에이전트의 입력과 사람의 입력을 구분할 수 없습니다. 언제, 무엇을, 몇 건 대조·수정했는지 기관 쪽에 남기고(실명 대신 이용자 ID), 동기화에 든 시간과 불일치 건수도 적습니다. 이 숫자는 정부 시스템에 API나 연계를 요구할 근거가 됩니다.

## 지시문에 넣을 것

Aside 공식 도움말도 결과, 쓸 사이트와 파일, 피할 행동을 적으라고 합니다. 이 작업에서는 다음을 빠뜨리지 않습니다.

- 대상 시스템과 화면, 원본 시트
- 할 일: 대조만인지, 입력까지인지
- 하지 말 것: 저장, 제출, 결재 요청, 삭제, 다른 메뉴 이동
- 멈추고 사람을 부를 때: 원본이 비었거나 이상할 때, 인증 화면이 나올 때

## 도구 설정에서 볼 것

Aside 공식 도움말 기준입니다(2026년 9월 확인, `../platform-facts.md`).

- **저장된 비밀번호**: AI 에이전트 접근 정책의 기본값이 `Always allow`입니다. `While unlocked`나 `Never`로 바꿉니다.
- **메모리**: 켜 두면 방문 기록과 작업 내용으로 메모리를 만듭니다. 이 작업 전에는 끄거나 보존 기간을 짧게 둡니다.
- **모델 연결**: 개인 구독 대신 기관이 결제하는 API 키로 연결합니다(4번).
- **다른 탭**: 에이전트는 화면 속 문장을 명령으로 착각할 수 있습니다(프롬프트 인젝션). 작업 중에는 관계없는 사이트 탭을 닫아 둡니다.

## 판정 체크리스트

- 대안(복사용 화면)을 한 줄로 제안했고, 사용자가 골랐다
- 운영 기관 약관과 위수탁 협약을 확인했다. 못 했으면 "기관 확인 대기"로 적었다
- AI 전송 조건(DPA, 국외이전 근거, 민감정보 동의, 처리방침)을 갖췄다
- 원본을 정했고, 원본이 이상하면 멈추게 했다
- 로그인과 추가 인증은 사람이 하고, 저장·제출·결재 요청 버튼도 사람이 누른다
- 작업 로그를 남길 곳을 정했다

## 확인 필요

- 쓰려는 정부 시스템 운영 기관(희망이음은 한국사회보장정보원)의 자동화 도구 정책과 화면 데이터의 외부 전송 허용 여부
- 에이전트 브라우저가 화면 내용을 자기 회사 서버와 모델 사업자에게 어떻게 보내는지, 학습에 쓰는지, 기관용 DPA가 있는지. Aside는 2026년 9월 기준 공식 도움말에 이 내용이 없습니다.
- 개인정보보호위원회 생성형 AI 안내의 최신판
