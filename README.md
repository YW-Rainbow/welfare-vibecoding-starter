# 사회복지 바이브코딩 스타터팩

> 코드 템플릿이 아니라, 코드를 짜기 전에 해야 할 판단을 담은 문서 묶음입니다.
> 어떤 플랫폼에, 어떤 법적 근거로, 무엇을 지키며 만들지 — 이 판단을 AI에게 들려 보내세요.

사회복지 현장에서 AI로 업무 앱을 만들다 보면(바이브코딩), 정작 어려운 것은 코드가
아니라 선택입니다. GAS로 만들지 Cloudflare로 만들지, 개인정보는 어디에 두어야 하는지,
국외이전 동의는 언제 받아야 하는지, 담당자가 바뀌면 누가 이어받을 수 있는지.
이 저장소는 그런 질문에 답하기 위한 판단 기준을 모아 두었습니다.

## 무엇을 위한 저장소인가

목적은 앱 그 자체가 아닙니다. 반복되는 행정을 줄여서 **당사자를 만나는 시간**을
되찾는 것입니다. 그래서 순서를 지킵니다. 자동화에 앞서 먼저 묻습니다 — 이 절차는
법령이나 지침이 요구하는 일인가, 기관의 관행이라 없앨 수도 있는 일인가.
**없애고, 줄이고, 남는 것만 자동화합니다.** 문제를 찾을 때도 사람을 탓하지 않되,
시스템의 문제는 흐리지 않고 또렷하게 정의합니다. 사람에게는 강점관점,
시스템에는 문제해결관점입니다.

개발을 몰라도 괜찮습니다. 모든 문서는 비개발자를 전제로 썼고, 낯선 용어는
[`glossary.md`](glossary.md)(용어사전)에 전부 풀어 두었습니다. guide.md를 받은 AI는
용어를 풀어 설명하면서 안내하게 되어 있습니다.

## 사용법 — 두 가지 방법이 있습니다

### 방법 1. 에이전트형 도구를 쓴다면: 클론하고, 바로 말을 거세요

Claude Code, Codex 같은 에이전트형 도구를 쓴다면 이 한 줄이 준비의 전부입니다.

```
git clone https://github.com/YW-Rainbow/welfare-vibecoding-starter.git
```

클론한 폴더에서 에이전트를 열고, 만들고 싶은 앱을 이야기하세요.

> "우리 기관 프로그램일지 앱을 만들려고 해. 사진도 회기당 2~3장 올라가."

저장소 루트의 CLAUDE.md(AGENTS.md)가 에이전트에게 일하는 순서를 알려주기 때문에,
"가이드를 참고해"라고 말할 필요도 없습니다. 에이전트가 guide.md의 순서대로
절차부터 점검하고(관문), 몇 가지를 물은 뒤(문진), 플랫폼을 추천합니다.
판정이 끝나면 이 폴더가 그대로 앱 프로젝트가 됩니다 — 에이전트가 판정 결과를
`DECISION.md`에 기록하고, 선택한 경로의 규칙을 CLAUDE.md에 통합하고, 판정용
문서와 고르지 않은 경로의 규칙 파일은 정리한 뒤(인수인계·파기 대장 등 운영
문서는 남깁니다) 개발을 시작합니다.

### 방법 2. 채팅 AI를 쓴다면: guide.md 한 장을 첨부하세요

Claude·ChatGPT·Gemini 대화창을 쓴다면
[guide.md를 내려받아](https://raw.githubusercontent.com/YW-Rainbow/welfare-vibecoding-starter/main/guide.md)
(링크를 열고 우클릭 → 다른 이름으로 저장) 대화에 첨부하고, 똑같이 만들려는 앱을
설명하세요. 판단은 이 파일 하나로 충분하고, 다음 단계에 필요한 파일(경로별
`rules/`, 운영용 `ops/`)은 AI가 판단 결과와 함께 내려받기 주소를 알려줍니다.

어느 방법이든, 모르는 용어가 나오면 [`glossary.md`](glossary.md)(용어사전)를 펴세요.

## 판정 트리 (요약)

```
IF 민감정보(건강·장애·상담기록) 대량·핵심 시스템
      → 기성 제품 사용. 바이브코딩 결과물 금지 (동의 여부 무관)
ELIF 민감정보 소량·보조적 + 법정 동의 확보(제23조·제28조의8)
      → Supabase(서울) Pro + 마스킹 후 LLM 분석 허용
ELIF 1인용 도구 (데이터 공유 불필요)
      → 로컬 퍼스트 (브라우저 저장, 서버 없음)
ELIF 연간 5만 행 이상 OR 종단 분석(연도 비교·이용자 추이) 필요
      → Cloudflare Pages + Supabase(서울) Pro
      └ MS 비영리 테넌트 + 전담 관리자 있으면 → Azure 국내 리전 풀스택 검토
ELIF Google Workspace 조직 내부용 소규모
      → GAS (+ rules/gas.md의 필수 설정)
ELSE (개인정보 없음: 안내·계산기·공개 대시보드)
      → Cloudflare 올인원 (Pages + Workers + D1 + R2)
```

전체 판정 로직은 [`guide.md`](guide.md)에, 요건별 법적 근거는
[`requirements.md`](requirements.md)에 있습니다.

## 이 저장소의 뼈대가 되는 생각

**요건은 정해져 있고, 플랫폼은 그 요건을 채우는 방식만 다릅니다.**

개인정보를 다루는 앱이 갖춰야 할 것들 — 인증, 권한, 백업, 삭제 완결성, 파기 대장 —
은 개인정보보호법과 운영 현실에서 나오기 때문에, 어떤 플랫폼을 골라도 똑같이
요구됩니다. 플랫폼마다 다른 것은 그 요건을 벤더가 알아서 해 주는지(◎), 설정만
하면 되는지(○), 직접 만들어야 하는지(△), 사람이 계속 관리해야 하는지(●)뿐입니다.

그래서 이 저장소는 "어떤 플랫폼이 좋은가"를 말하지 않습니다. 대신
**"이 플랫폼을 고르면 무엇이 내 숙제로 남는가"**를 보여줍니다. 접근 기록,
파기 대장, 동의서, 인수인계는 어느 플랫폼도 대신해 주지 않으니까요.

## 구조

```
├── CLAUDE.md / AGENTS.md   # 에이전트형 도구용 시작 지시 (클론하면 자동으로 읽음)
├── guide.md            # AI에게 주는 본체: 판정 순서 + 원칙 + 요건 매트릭스
├── requirements.md     # 공통 요건 12개의 정의와 법적 근거 (거의 바뀌지 않음)
├── record-integrity.md # 기록 무결성 — "이 기록은 증거인가"를 묻는 축과 8원칙
├── glossary.md         # 용어사전 — 모든 전문용어를 현장의 말로 풀이
├── rules/              # 플랫폼별 시공 지침 = AI 규칙 파일 (자주 바뀜)
│   ├── agentic.md      #   에이전트형 개발·배포 공통 규칙 (Claude Code 등)
│   ├── gas.md          #   GAS + 구글시트
│   ├── cf-supabase.md  #   Cloudflare Pages + Supabase(서울)
│   └── cf-only.md      #   Cloudflare 올인원 (개인정보 없는 앱 전용)
├── ops/                # 플랫폼이 해 주지 못하는 것들: 사람과 절차
│   ├── handover.md     #   인수인계 체크리스트
│   ├── destruction-log.md  # 개인정보 파기 대장 양식
│   ├── consent-notes.md    # 동의서·처리방침 작성할 때 주의할 점
│   └── consent-form-sample.md  # AI 활용 동의서 샘플 (양식)
└── LICENSE.md          # 문서 CC BY 4.0 / 코드 MIT
```

## 함께 쓰는 저장소

이 저장소는 판단을 맡습니다. 경로가 정해지면 아래 실행 발판(시작 템플릿)으로 넘어가세요.

| 경로 | 실행 발판 |
|---|---|
| 경로 C (GAS) | [apps-script-vibe-starter](https://github.com/YW-Rainbow/apps-script-vibe-starter) — clasp 설정, AI 에이전트 규칙(AGENTS.md), PRD 양식이 갖춰져 있어 클론하면 바로 시작할 수 있습니다 |
| 그 외 경로 | 템플릿 기여를 기다립니다 (아래 기여 안내 참고) |

순서는 이렇습니다. **guide.md로 판단하고, 해당 rules/ 파일을 적용하고, 실행 발판을
클론해서 개발을 시작합니다.**

## 기여

- **플랫폼 추가**: 요건 매트릭스에 열 하나, `rules/`에 파일 하나 — 이것이 기여
  한 단위입니다.
- **실행 발판 추가**: 경로별 시작 템플릿 저장소(예: CF+Supabase용)를 만들어 링크하는
  것도 훌륭한 기여입니다. apps-script-vibe-starter가 본보기입니다.
- **사실 갱신**: 가격, 무료 한도, 제도는 금방 낡습니다. 각 문서의 기준일을 확인하고
  이슈나 PR로 알려주세요.
- **현장 사례**: "이 조합으로 이런 앱을 만들었다", "이런 문제를 겪었다" 같은
  이야기가 가장 귀한 기여입니다.

## 알아둘 것

- 이 문서들은 **법률 자문이 아닙니다.** 실무 참고용이며, 민감정보를 다루는 시스템은
  도입 전에 개인정보 전문가의 검토를 받으세요.
