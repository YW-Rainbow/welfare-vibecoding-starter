# 사회복지 바이브코딩 스타터팩

> 코드 템플릿이 아니라, 코드를 짜기 전에 필요한 판단을 모아 둔 문서 묶음입니다.
> guide.md를 AI에게 주면, 무엇을 어디에 어떻게 만들지부터 함께 정리해 줍니다.

## 왜 만들었나

지금까지 우리는 내 손에 맞지도 않는 프로그램을 억지로 쓰고, 데이터가 흩어져
스스로 신뢰를 깎아먹으며, 불필요한 반복 행정에 소중한 시간과 에너지를
쏟아왔습니다. 정부가 의무 사용을 요구하는 프로그램은 업데이트도 안 되고, 업체가
만들어 주는 건 비싸다는 핑계 뒤에서 현장의 비효율과 무력감을 감내해 왔습니다.
이미 충분히 잃었습니다.

바이브코딩은 그 자리를 되찾는 일입니다. 우리가 겪는 고통을 해결할 도구를 스스로
고르고, 그 도구를 운영할 규칙과 데이터 보호 장치를 동료들과 함께 정하고, 불편하면
내일 당장 함께 고쳐 쓰는 것. 실무자가 내 손에 맞는 도구를 직접 만드는 **현장
자율성과 도구 주권의 회복**입니다.

그런데 실제로 해 보면 막히는 곳은 코드가 아닙니다. GAS로 갈지 Cloudflare로 갈지,
개인정보는 어디에 두어야 하는지, 국외이전 동의는 받아야 하는지, 내가 그만두면 이
앱은 누가 맡는지. 코드는 AI가 짜 주지만 이런 선택은 사람 몫으로 남고, 많은 동료가
그 앞에서 멈춥니다.

이 저장소는 그 문턱을 낮추려고 만들었습니다. 개발을 몰라도 됩니다. 판단에 필요한
것을 순서대로 적어 두었고, AI에게 그대로 건네면 함께 정리해 줍니다. 먼저 밤을 새워
헤맨 사람이 뒤에 오는 동료를 위해 길을 적어 둔 것입니다. 혼자 다 떠안지 않아도
됩니다.

## 이 저장소가 하려는 일

앱을 만드는 일 자체가 목적이 아닙니다. 반복되는 행정을 줄여서 당사자를
만날 시간을 되찾고자 합니다. 그래서 자동화보다 앞서는 질문이 있습니다. 이 절차는
법령이나 지침이 시키는 일인가, 아니면 우리 기관의 관행일 뿐이어서 없애도 되는
일인가. 없애고, 줄이고, 남는 것만 자동화합니다.

문제를 찾을 때는 사람을 탓하지 않습니다. 다만 시스템의 문제만큼은 흐리지 않고
또렷하게 말합니다. 사람에게는 강점관점, 시스템에는 문제해결관점. 이 저장소의 문서는 모두
그 순서를 지키도록 짰습니다.

그리고 만들 수 있는지 묻기 전에 만들어도 되는지 묻습니다. 근태를 정확히
관리하자는 목적은 옳습니다. 그렇다고 바꿀 수 없는 지문까지 내놓으라 할 일은
아닙니다. 뜻이 좋고 목적이 옳다고 수단까지 옳은 것은 아니니까요. 사람을 기록하는
앱을 만들기 전에 따져 볼 다섯 질문을 [`ethics.md`](ethics.md)에 모았습니다. 가장 앞선
기술이 아니라 그 자리에 맞는 기술을 고르는 이야기, 만드는 일의 부담이 한 사람에게
쏠리지 않게 하는 이야기도 함께 있습니다. 만들지 말라는 목록이 아닙니다. 무엇을
안고 가는지 알고 정하자는 목록입니다.

개발을 몰라도 됩니다. 문서 전부를 비개발자 기준으로 썼고, 낯선 말은
[`glossary.md`](glossary.md)(용어사전)에 풀어 두었습니다. guide.md를 받은 AI도
용어를 풀어 가며 안내합니다.

## 쓰는 법

### Claude Code 같은 에이전트를 쓴다면

준비는 클론 한 번이면 끝납니다.

```
git clone https://github.com/YW-Rainbow/welfare-vibecoding-starter.git
```

클론한 폴더에서 에이전트를 열고, 만들고 싶은 앱을 이야기하세요.

> "우리 기관 프로그램일지 앱을 만들려고 해. 사진도 회기당 2~3장 올라가."

폴더 안의 CLAUDE.md가 에이전트에게 일하는 순서를 알려 주니, 따로 시킬 일이
없습니다. 에이전트는 먼저 그 일이 꼭 필요한 절차인지 묻고, 몇 가지를 확인한 뒤
플랫폼을 골라 줍니다. 판정이 끝나면 이 폴더가 그대로 앱 프로젝트가 됩니다.
왜 이렇게 골랐는지 DECISION.md에 적어 두고, 고른 경로의 규칙만 남긴 채
나머지 문서를 정리한 다음 개발을 시작합니다.

### 채팅창에서 쓴다면

guide.md 한 장이면 됩니다.
[여기서 내려받아](https://raw.githubusercontent.com/YW-Rainbow/welfare-vibecoding-starter/main/guide.md)
(링크를 열고 우클릭, 다른 이름으로 저장) Claude나 ChatGPT 대화창에 붙이고,
똑같이 만들려는 앱을 이야기하세요. 다음 단계에 필요한 파일은 AI가 내려받을
주소와 함께 알려 줍니다.

어느 쪽이든, 모르는 말이 나오면 [`glossary.md`](glossary.md)를 펴세요.

### 서식 전체를 정리하고 싶다면

앱 하나가 아니라 기관의 양식을 통째로 손보고 싶다면
[`form-audit.md`](form-audit.md)에서 시작하세요. 양식을 다 꺼내 놓고
세 번 묻고 한 번 확인해서, 없앨 양식과 그대로 둘 양식, 앱으로 만들 양식을
구분합니다. 없앨 양식을 없애는 일이 첫 성과이고, 앱 후보 판정을 받은 양식만
guide.md로 내려옵니다.

앱을 여러 개 만들 생각이거나 담당자마다 각자 파일로 관리하고 있다면
[`ssot.md`](ssot.md)를 함께 보세요. 무엇을 원본으로 삼을지 정하지 않고 앱만
늘리면, 같은 어르신이 파일마다 다른 이름으로 앉게 됩니다.

## 판정 트리 (요약)

```
IF 생체인식정보(지문·얼굴·홍채)를 받는 앱
      → 무조건 S등급. 다른 길(카드·QR·PIN)부터 살펴보고,
        그래도 간다면 ethics.md 2번을 확인하고 정한 까닭을 남긴다
ELIF 민감정보(건강·장애·상담기록) 대량·핵심 시스템
      → 기성 제품 사용. 바이브코딩 결과물 금지 (동의 여부 무관)
ELIF 민감정보 소량·보조적 + 법정 동의 확보(제23조·제28조의8)
      → Supabase(서울) Pro + 마스킹 후 LLM 분석 허용
ELIF 1인용 도구 (데이터 공유 불필요)
      → 로컬 퍼스트 (브라우저 저장, 서버 없음)
ELIF 연간 5만 행 이상 OR 종단 분석(연도 비교·이용자 추이) 필요
      → Cloudflare Pages + Supabase(서울) Pro
      └ MS 비영리 테넌트 + 전담 관리자 있으면 → Azure 국내 리전 풀스택 검토
ELIF Google Workspace 조직 내부용 소규모
      → GAS (+ rules/gas.md의 필수 설정)
ELSE (개인정보 없음: 안내·계산기·공개 대시보드)
      → Cloudflare 올인원 (Pages + Workers + D1 + R2)
```

판정을 내리는 전체 순서는 [`guide.md`](guide.md)에, 요건별 법적 근거는
[`requirements.md`](requirements.md)에 있습니다.

## 이 저장소의 뼈대

문서 전체를 꿰는 생각은 하나입니다. 요건은 정해져 있고, 플랫폼은 그 요건을
채우는 방식만 다릅니다. 인증, 권한, 백업, 파기 같은 요건은 개인정보보호법과
운영 현실에서 나오기 때문에 어느 플랫폼을 골라도 똑같이 따라옵니다. 다른 점은
그 요건을 누가 채우느냐 하나뿐입니다. 벤더가 해 주거나(◎), 설정하면 되거나(○),
직접 만들거나(△), 사람이 계속 챙기거나(●).

그래서 이 저장소는 어떤 플랫폼이 좋다고 말하지 않습니다. 이 플랫폼을 고르면
무엇이 내 숙제로 남는지를 보여 줍니다. 접근 기록과 파기 대장, 동의서,
인수인계는 어떤 플랫폼도 대신해 주지 않으니까요.

├── glossary.md         # 용어사전 — 모든 전문용어를 현장의 말로 풀이
├── rules/              # 플랫폼별 시공 지침 = AI 규칙 파일 (자주 바뀜)
│   ├── agentic.md      #   에이전트형 개발·배포 공통 규칙 (Claude Code 등)

│   ├── destruction-log.md  # 개인정보 파기 대장 양식
│   ├── consent-notes.md    # 동의서·처리방침 작성할 때 주의할 점

├── tools/
│   └── form-audit-ledger.html  # 양식 점검 대장 — 함께 채우는 워크숍 도구 (Claude 아티팩트로 실행)
└── LICENSE.md          # 문서 CC BY 4.0 / 코드 MIT

| [vibecoding-pub](https://github.com/elbumlee/vibecoding-pub) | 이경태 선생님이 만들었습니다. 코딩을 모르는 사람이 말하듯 요청하면 열여섯 페르소나가 기획·디자인·코딩·오류수정·감사·배포를 나눠 맡는 Claude Code 스킬입니다. 눈여겨볼 곳은 `references/user-authority.md` — 사용자를 승인자가 아니라 결정권·의견권·최종결재권을 가진 주체로 두고, 에이전트가 그 권한을 어떻게 대해야 하는지 적어 두었습니다 |
